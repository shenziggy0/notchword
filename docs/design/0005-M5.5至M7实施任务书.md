## 0. 执行规则（每个任务都适用）

### 0.1 环境

- 在 macOS 15+ 上执行，只有 Command Line Tools（无完整 Xcode）。工作目录 `macos-starter/`。
- 开发门槛：每个任务结束时 `./build.sh` 成功（含随包词库自检）且 `./test.sh` 全部通过。这不是验收，只是"不把仓库留在坏状态"。
- **不做实机验收**：M1—M7 全部实现后统一验收（见 §6）。需要人工操作才能确认的行为（TCC 授权、浏览器、刘海屏、签名更新），任务内只保证代码路径完整、可编译，并在汇报中列出"待统一验收"项。

### 0.2 开发原则

1. **优先复用**：动手前检索现有代码。新入口一律经 `LookupCoordinator.submit` 与 `PanelController`；翻译一律经 `TranslationCoordinator`；SQLite 访问一律经 `Support/SQLite.swift`（B3 产出）。新增模块须能说明现有实现为何不能复用（0004 §2.2 已列）。
2. **保持整洁**：沿用现有文件与命名，不按架构文档 §13 重组；被替代的代码（固定热键、`permission.prompted`）同一任务内删除，不留死代码、注释掉的代码或临时开关。
3. **拒绝过度设计**：不建插件式注册、不为 Windows 或 M8 预留抽象；`Entitlements.allows` 只在 0004 指定的三处调用。
4. **测试克制**：只写本文各任务"测试"一栏列出的用例；不写防御性、极端边界或重复实现逻辑的测试。
5. **调研有据**：文档与代码不一致时以代码为准，并在汇报中指出差异。

### 0.3 禁止事项

- 不读取、对照、复制参考产品 Dipword 的代码、内嵌脚本、选择器表原文、数据库与素材；不修改 `docs/dipword-analysis/`。
- 不修改 swclaw。
- 不用 mock 代替真实服务做"已跑通"的结论；联网翻译、AI 起草均为真实调用、真实计费。
- 日志不写查询正文、字幕正文、密钥。
- 界面不出现 Pro / 升级 / 购买 字样。
- 不申请 Apple Developer、不做公证、不启用 hardened runtime。

### 0.4 提交与汇报

- **未经用户同意不提交、不推送**。每个任务完成后停下汇报，由用户决定是否提交；提交说明一律中文。
- 汇报格式：改动文件列表 → 开发门槛结果（build / test 输出摘要）→ 测试用例结果 → 与设计不一致之处及理由 → 待统一验收项 → 遗留问题。
- 任务内遇到设计未覆盖、且会改变方向的问题，停下提问，不自行扩大范围。

### W3 AI 起草（Cursor grok-4.7）

- **产出**：`build_wordparts.py --coverage-db …` 退出码 0；汇报实际批次数、失败数、覆盖统计。

### R2 `ScreenText` 屏幕识别

- **改动**：新增 `Capture/ScreenText.swift`。
- **步骤**：
  1. `recognize(rect:on:) async throws -> String`：`SCScreenshotManager` 截取屏幕指定区域 → `VNRecognizeTextRequest`（`en-US`，先 `.fast`，结果为空或失败再 `.accurate`）→ 聚行。
  2. 聚行逻辑抽为纯函数 `mergeLines([识别框]) -> [String]`：按 y 接近程度归行，行内按 x 排序。
  3. 截图只在内存中，不写磁盘；无权限返回明确错误类型。
- **测试**：`mergeLines` 三个框（y = 0.80 / 0.81 / 0.60）→ 两行、行内按 x 排序（1 条）。

### S1 `BrowserBridge`

- **改动**：新增 `Subtitle/BrowserBridge.swift`。
- **步骤**：

- **测试**：无（依赖真实浏览器）。

### S2 `subtitle.js`

- **改动**：新增 `Resources/subtitle.js`（`Package.swift` 资源 `.copy`）。**自研**，不参考 Dipword 脚本文本。
- **步骤**：
  1. 幂等安装：重复注入不重复挂监听；状态挂在一个自有命名的全局对象上。
  2. 选面积最大的可见 `<video>`；`mediaKeys` 存在 → `drm`；广告中（站点特征）→ `ad`；能取到字幕 → `dom`；否则 → `screen`。
  3. 取字幕顺序：原生 `textTracks`（showing 且有 cues）→ 站点选择器（YouTube、Netflix、Bilibili、Prime Video，**在真实页面核对后写入**，并在文件内注明核对日期）→ 通用兜底（自 video 向上 5 层容器内的可见文本）。
  4. `MutationObserver` 合并短时间内的变化，维护最近 80 条历史（文本 + 时间点）。
  5. 返回 JSON：`hist`、`times`、`live`、`paused`、`now`、`note`（`ok/ad/drm/nosub`）、`videoRect`（视口内归一化矩形，供 OCR）、`site`。
  6. 命令：`state`、`pause`、`play`。
  7. 只读取字幕与视频状态，不读 Cookie、表单、账号信息。
- **测试**：无（依赖真实页面）；汇报中列出已核对的站点与日期。

### S3 `SubtitleTracker` + `SentenceMerger`

- **改动**：新增 `Subtitle/SubtitleTracker.swift`、`Subtitle/SentenceMerger.swift`。
- **步骤**：
  1. Tracker 仅在 `trigger.videoSubtitles` 开启、前台为支持浏览器时以约 2Hz 轮询 `state`；前台切走即停。
  2. `note == screen` 且 `trigger.screenSubtitles` 开启时，用 `videoRect` 换算成屏幕坐标调用 `ScreenText`；Firefox 等不支持的浏览器直接走 OCR（以前台窗口区域为范围）。
  3. 内容变化才推送；`SentenceMerger` 纯函数：碎片 → 句子（句末标点 / 间隔 > 1s / 说话人标记 / 已满 3 条）。
- **测试**：`SentenceMerger` 输入 `"so we"`、`"went home."`（间隔 0.2s）、`"Then"`（间隔 1.5s）→ `["so we went home.", "Then"]`（1 条）。
